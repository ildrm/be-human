# Authentication and authorization

Passwords are hashed with Argon2id (19 MiB, three iterations, one lane in the current profile). Login creates a 256-bit opaque token. The database stores a purpose-separated HMAC-SHA-256 digest using `SESSION_SECRET`; CSRF tokens and IP addresses use distinct HMAC purposes. Existing unprefixed HMAC digests remain readable until their sessions expire. The browser receives the session token through an HttpOnly, SameSite=Lax cookie, Secure in production. Sessions expire after 30 days and can be revoked; `last_seen_at` updates at most once every 15 minutes per active session.

Roles authorize platform actions; ownership and relationship attributes authorize user resources. A role alone never grants household-private content. The intended policy input is `(actor, action, resource owner, household relationship, explicit grant, privacy class, validity time)`. Deny is the default. A pending-deletion session can access only account, privacy-request, cancellation, and logout routes. Household goal-view access requires an explicit grant bound to the creating household and active membership there dating back to the grant. A grant is suspended while either account is pending deletion.

Current production blockers: TOTP/passkeys, recovery codes, token-family reuse detection, account recovery, global rate limiting, support-role elevation controls, and complete per-endpoint policy tests.
